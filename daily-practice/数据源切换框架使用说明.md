# 数据源切换框架使用说明

## 概述

这是一个通用的数据源切换框架，专门解决项目中频繁出现的MySQL/TiFlash数据源切换问题。框架支持：

- ✅ **简化if/else逻辑** - 避免重复的条件判断代码
- ✅ **异常兜底机制** - TiFlash异常时自动切换到MySQL
- ✅ **数据结构转换** - 处理不同数据源返回Entity结构差异
- ✅ **配置化管理** - 支持动态配置切换策略
- ✅ **多种使用方式** - 简单方法、构建器模式、注解驱动

## 核心组件

### 1. 数据源策略 (DataSourceStrategy)
```java
public enum DataSourceStrategy {
    MYSQL("mysql", "MySQL数据源"),
    TIFLASH("tiflash", "TiFlash数据源"),
    DEFAULT("default", "默认数据源");
}
```

### 2. 数据转换器 (DataConverter)
```java
// TiFlashUser转换为User
DataConverter<TiFlashUser, User> converter = UserConverter.TIFLASH_TO_USER;
```

### 3. 数据源切换助手 (DataSourceSwitchHelper)
提供多种便捷的切换方法。

## 使用方式

### 方式1：简单的二选一切换

**原始代码：**
```java
if (WeConfig.getBooleanConfig("switch", false)) {
    // 使用mysql
    userDao.select();
} else {
    // 使用tiflash
    tiflashUserDao.select();
}
```

**优化后：**
```java
return DataSourceSwitchHelper.switchBetween(
    "user.query.switch",
    () -> userMapper.selectByPrimaryKey(id),      // MySQL
    () -> tiflashUserMapper.selectByPrimaryKey(id) // TiFlash
);
```

### 方式2：构建器模式

```java
return DataSourceSwitchHelper.<User>builder()
    .configKey("user.query.switch")
    .defaultValue(false)
    .mysql(() -> userMapper.selectByPrimaryKey(id))
    .tiflash(() -> tiflashUserMapper.selectByPrimaryKey(id))
    .execute();
```

### 方式3：带数据转换器

当不同数据源返回的Entity结构不同时：

```java
return DataSourceSwitchHelper.<User>builder()
    .configKey("user.converter.switch")
    .defaultValue(false)
    .mysql(() -> userMapper.selectByPrimaryKey(id))
    .tiflashWithConverter(
        () -> tiflashUserMapper.selectByPrimaryKey(id), // 返回TiFlashUser
        UserConverter.TIFLASH_TO_USER                   // 转换为User
    )
    .execute();
```

### 方式4：带异常兜底

当TiFlash查询可能异常时，自动切换到MySQL：

```java
return DataSourceSwitchHelper.<User>builder()
    .configKey("user.fallback.switch")
    .defaultValue(false) // 默认使用TiFlash
    .mysql(() -> userMapper.selectByPrimaryKey(id))
    .tiflashWithConverter(
        () -> tiflashUserMapper.selectByPrimaryKey(id),
        UserConverter.TIFLASH_TO_USER
    )
    .mysqlAsFallback(() -> {
        // TiFlash异常时的兜底逻辑
        return userMapper.selectByPrimaryKey(id);
    })
    .execute();
```

### 方式5：复合场景

转换器 + 异常兜底 + 条件查询：

```java
return DataSourceSwitchHelper.<List<User>>builder()
    .configKey("user.age.advanced.switch")
    .defaultValue(false)
    .mysql(() -> {
        return userMapper.selectAll().stream()
            .filter(user -> user.getAge() >= age)
            .toList();
    })
    .tiflashWithConverter(
        () -> tiflashUserMapper.selectByAge(age),
        UserConverter.TIFLASH_LIST_TO_USER_LIST
    )
    .mysqlAsFallback(() -> {
        return userMapper.selectAll().stream()
            .filter(user -> user.getAge() >= age)
            .toList();
    })
    .execute();
```

## 配置管理

在 `application.properties` 中配置开关：

```properties
# 用户查询开关：true=MySQL, false=TiFlash
user.query.switch=false
user.list.switch=false
user.converter.switch=false
user.fallback.switch=false

# 全局开关
datasource.switch=false
```

## 最佳实践

### 1. 配置命名规范
```properties
# 建议格式：{业务模块}.{操作类型}.switch
user.query.switch=false
order.list.switch=true
product.search.switch=false
```

### 2. 异常处理
```java
.mysqlAsFallback(() -> {
    logger.warn("TiFlash查询失败，使用MySQL兜底");
    return fallbackLogic();
})
```

### 3. 性能考虑
- 配置会被缓存，避免频繁读取
- 转换器使用函数式接口，性能开销小
- 支持批量操作的转换器

### 4. 监控和日志
框架会自动记录：
- 数据源切换日志
- 异常兜底日志
- 配置加载日志

```java

    };
```

## 总结

这个框架彻底解决了项目中频繁出现的数据源切换问题：

1. **代码简化** - 从复杂的if/else变成一行配置
2. **异常安全** - 自动兜底，提高系统稳定性
3. **结构适配** - 自动处理不同数据源的Entity差异
4. **配置灵活** - 支持动态配置，便于运维管理
5. **易于扩展** - 支持新增数据源和自定义转换逻辑

使用这个框架后，您的代码将更加简洁、安全和易维护！
